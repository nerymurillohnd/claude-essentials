# Auditing Excel workbooks (.xlsx, .xlsm)

## Contents

1. Procedure
2. Reading the summary
3. Cached, recomputed and missing values
4. Formula consistency
5. Pitfalls

## 1. Procedure

1. `extract_xlsx.py summary FILE` — every
   sheet with its state (visible, hidden, veryHidden), dimension, cell and formula
   counts, formulas without a cached value, error cells, formula outliers, merged
   ranges, hidden rows and columns; plus defined names, external links and macros.
2. `extract_xlsx.py cells FILE --sheet S [--range A1:D20]` for the cells the
   question is about. Omit `--range` to stream the whole sheet.
3. `extract_xlsx.py recompute FILE --sheet S` only when the summary shows
   formulas without cached values and the question needs their results.

## 2. Reading the summary

| Summary field | What it tells you | What to report |
| --- | --- | --- |
| `state=hidden` / `veryHidden` | the sheet is invisible in Excel but part of the file | its content, and that it is hidden |
| `formulas_without_cached_value` | the file was written by a program and never calculated | those results are unknown until recomputed |
| `error_cells` | `#REF!`, `#DIV/0!`, `#N/A` and similar stored results | each error with its cell |
| `formula_outliers_by_column` | a formula whose shape differs from the rest of its column | judge it: a total row is expected, a single odd row in a data column is a likely mistake |
| `external_link` | formulas that read another workbook (`[1]Sheet!A1`) | the cached value is the only data; never recompute over it |
| `macros=YES` | the file contains a VBA project | mention it; the scripts never run or inspect macros |
| `merged` | merged ranges; only the top-left cell holds the value | cite the top-left cell |

## 3. Cached, recomputed and missing values

- **cached** — the value the spreadsheet application stored when it last
  calculated. This is what a person opening the file in Excel sees.
- **missing** — the cell has a formula but no stored value (common in files
  generated by scripts). Report it as not calculated.
- **recomputed** — `recompute` evaluated the formula with a small safe evaluator
  (arithmetic, same-sheet references and ranges, SUM, AVERAGE, MIN, MAX, COUNT,
  COUNTA, ROUND, ABS, DATE). Anything else is reported as `NOT RECOMPUTED` with
  the reason. Label every recomputed number as such.

A cached value that looks wrong is still what the file says; report it. `recompute`
never evaluates a cell that has a cached value, so when a cached total looks
inconsistent, list the cells it covers with `cells FILE --sheet S --range <range>`
and put the suspected discrepancy under **Needs human judgment** with both
locators, rather than a total of your own.

## 4. Formula consistency

The summary compares each formula with the others in its column in relative
(R1C1-style) form. A data column where one row uses a different formula is the
classic spreadsheet error (a hard-coded number, a range that stops one row
short). Report outliers with both formulas and let the user decide.

## 5. Pitfalls

- **Percentages and dates are formats.** 0.15 displayed as 15% and serial 46276
  displayed as 2026-09-11 are the same stored numbers; `cells` shows both forms
  when the cell's number format says so.
- **`_xlfn.` prefixes** mark functions newer than Excel 2007 (XLOOKUP, IFS…).
  They are normal; Excel hides the prefix.
- **Dynamic arrays** (FILTER, UNIQUE, SORT, SEQUENCE) spill from one formula
  cell; only the anchor cell holds the formula.
- **A clean error scan does not prove correctness.** Off-by-one ranges return
  numbers, not errors; that is why the outlier check exists.
- **Legacy .xls or a password** exits `3`. Report as not reviewed.
